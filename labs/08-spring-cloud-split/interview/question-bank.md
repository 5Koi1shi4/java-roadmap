# 实验八面试追问

## 为什么先拆身份服务？

身份接口和交易用例的职责清楚，验证码、密码验证、Token 签发可以独立部署。先拆这一边界能练习服务发现、网关和跨进程认证，同时保留库存、支付、退款与售后在一个交易数据库事务内，避免同时引入分布式资金事务。

## Gateway 已经认证，业务服务为什么再次验签？

业务服务可能被直接访问，也不能将客户端可构造的 Header 当成可信身份。两层分别验证身份服务的 RS256 签名和 `kid/iss/aud/sub/roles/iat/exp` 契约，业务权限始终从 Token 得到。Gateway 清理伪造身份 Header 只是入口防护的一部分。

## 为什么用 RS256 和 JWKS？

身份服务独占私钥，资源服务器只获得公钥，降低验证服务被攻破后伪造 Token 的风险。JWKS 通过 `kid` 选择公钥；未知密钥不能作为放行理由。代价是需要管理公钥获取、缓存、轮换和冷启动失败语义。

## 身份服务停机后，业务请求能否继续？

已缓存公钥且 Token 未过期时可以继续验签，登录依赖身份服务仍会失败。冷启动没有可用公钥时不能放行。必须分别验证热缓存、冷启动、未知 `kid` 和恢复，不把一次正常请求当成所有故障场景的证据。

## 为什么禁止 Gateway 自动重试写请求？

连接中断不等于下游事务未提交，重试注册、验证码或交易命令可能产生重复副作用。原交易用例的显式幂等键继续负责重放语义；网关不替客户端重建写请求，也不返回虚构的成功结果。

## 如何证明数据库所有权不是口头约定？

身份和交易分别使用本库迁移账号与运行账号，运行账号只授予必要 DML 权限。真实 MySQL 测试分别尝试跨库读取并断言被拒绝；生产业务模块不依赖对方领域模型，不用跨库外键或查询补足事务。

## 截止调度和筹资为什么可能死锁？

若截止扫描先锁状态/截止时间二级索引再等待主键，筹资先锁主键再更新索引，就形成反向等待。候选扫描只读取提示列表，逐项事务按主键加锁，再用当前状态、金额与数据库截止时间条件更新。回归测试应控制真实主键锁，观察目标记录等待，不能通过吞掉数据库异常来宣称串行化。
