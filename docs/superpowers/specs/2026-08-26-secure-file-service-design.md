# 实验六：安全文件服务与 MinIO 设计

## 1. 背景与目标

阶段六建设一个独立、可运行、可验证的安全文件服务实验。实验聚焦文件上传、内容识别、物理去重、逻辑权限、流式下载和对象存储故障恢复，不重复实现完整认证中心。

实验覆盖以下学习目标：

- 使用 Multipart 和流式 IO 上传文件，全程限制实际读取字节数，不把完整文件载入内存。
- 使用文件签名和 Apache Tika 识别真实类型，不信任扩展名或客户端 `Content-Type`。
- 使用 SHA-256、独立 Blob 元数据和随机 Object Key 实现全局物理去重。
- 使用独立逻辑文件和 ACL 保持用户隔离，去重命中不通过接口显式泄露。
- 使用本地文件系统与 MinIO 两种 `ObjectStorage` 适配器验证端口边界。
- 使用上传会话、Blob 状态机、租约、owner token 和清理任务处理数据库与对象存储之间无法组成同一事务的问题。
- 使用私有文件、指定用户只读授权、统一 404、不可预测文件 ID 和安全审计验证访问控制。
- 使用单元测试、MySQL Testcontainers、MinIO Testcontainers、Toxiproxy 和真实 HTTP 测试形成验收闭环。

本实验不复用前五个实验的代码、数据库或运行环境。阶段六不建设完整用户中心、管理后台、病毒扫描平台、图片转码、分片上传、断点续传、CDN、通用工作流或消息队列。标准 JWT 作为后续可替换身份适配器，不属于本实验的实现范围。

## 3. 总体架构

项目采用四层结构：

- 领域层：定义逻辑文件、物理 Blob、只读授权、上传会话、清理任务及状态机，不依赖 Spring、数据库或 MinIO。
- 应用层：定义上传、下载授权、授权、撤权、逻辑删除、恢复和 Blob 清理用例及事务边界。
- 基础设施层：实现 MySQL 持久化、本地文件存储、MinIO 存储、身份解析、审计、调度和指标。
- API 层：处理 Multipart、协议校验、HTTP 错误映射和 UTF-8 JSON。

核心端口为：

```text
RequesterIdentityResolver  -> 解析当前请求主体
ObjectStorage              -> 临时写入、提交 Blob、读取、删除、签名
FileRepository             -> 逻辑文件及授权
BlobRepository             -> Blob 状态、引用计数和并发锁
UploadSessionRepository    -> 上传会话、租约和恢复状态
CleanupTaskRepository      -> 清理任务租约、claim token 与重试
AuditRecorder              -> 访问及权限变更审计
```

应用层只接收已经解析的正数用户 ID，不读取 HTTP Header，也不感知未来 JWT 的格式。本地和测试环境可显式开启可信用户头适配器；默认或生产环境没有安全身份适配器时必须启动失败。

对象存储永远不接受用户文件名作为路径。临时 Key、Blob Key、逻辑文件 ID、owner token、claim token 和内部请求关联 ID 均由加密安全随机源生成。内容哈希只保存在 Blob 元数据中，不出现在 Object Key、URL、API 响应、指标标签或普通业务日志中。

## 4. 文件范围与协议边界

第一版仅允许：

- JPEG
- PNG
- WebP
- PDF

单文件最大 20 MiB。上传读取器必须按实际字节数执行上限，不能只检查 Multipart 声明长度。超过上限时立即停止读取并进入失败补偿。

服务使用文件签名与 Apache Tika 识别真实媒体类型。识别结果必须属于白名单，并与安全扩展名和客户端声明类型相容。扩展名缺失可以接受，但扩展名存在且与真实类型冲突时拒绝。原始文件名只作为未经信任的展示输入；保存前移除 CR/LF、控制字符、路径分隔符和保留名称，并生成安全 ASCII fallback。下载时同时使用安全 fallback 和 RFC 5987 编码名称构造 `Content-Disposition`。

构造器和工厂方法拒绝空值、非正数 ID、非法大小、空白名称、不支持类型、非法状态和过期时间。反序列化边界拒绝未知字段和非法值，应用层不清洗协议数据。

## 5. 身份与权限模型

### 5.1 可插拔身份

`RequesterIdentityResolver` 是应用层唯一身份入口。可信 Header 适配器遵循以下约束：

- 仅允许在 `local` 或 `test` Profile 中注册。
- 必须同时设置显式开关；只满足 Profile 或只满足开关都不能启用。
- 非允许 Profile 尝试开启时，应用必须启动失败，而不是静默忽略。
- Header 名固定为 `X-Trusted-User-Id`，值必须是单个规范正整数。
- Header 缺失、重复、空白、包含非数字字符或超出范围时按未认证处理。
- README 明确要求可信网关先剥离所有外部同名 Header，再注入已认证身份；本地演示服务只绑定受控网络。

未来 JWT 适配器替换该实现时，不修改上传、ACL、下载或审计用例。

### 5.2 ACL

- 文件默认私有，所有者拥有读取、授权、撤权和删除权限。
- 所有者可以向指定用户授予或撤销只读权限。
- 被授权用户只能读取元数据、流式下载或申请下载链接，不能转授权或删除。
- 管理员角色不自动绕过 ACL。
- 对自身重复授权没有业务意义，返回 400。
- `(file_id, grantee_user_id)` 唯一约束保证重复授权幂等；重复撤权也保持幂等。

未认证请求返回 401。对已认证用户，不存在、已删除或无权访问的逻辑文件统一返回相同的 404 状态和错误结构。查询顺序、响应字段、日志级别和耗时优化不得故意暴露资源是否存在。系统不承诺抵抗精密计时侧信道，但不得提供显式去重、存在性或所有者信号。

## 6. 数据模型

### 6.1 上传会话

`upload_session` 保存：

- 随机会话 ID、上传者 ID、随机 tempKey。
- owner token、租约到期时间和会话过期时间。
- 状态 `RECEIVING`、`VALIDATED`、`FINALIZING`、`COMPLETED`、`FAILED`、`EXPIRED`。
- 实际大小、识别媒体类型、内容哈希和安全展示名。
- 关联 Blob ID、逻辑文件 ID、有限失败分类和时间戳。

owner token 与 `stored_blob.staging_owner_token` 建立显式关联。只有会话 ID、owner token、目标状态和有效租约同时匹配的执行者才能续租、推进或回收。租约到期后，新执行者生成新 token 条件接管；旧执行者的迟到结果影响行数必须为 0。

### 6.2 物理 Blob

`stored_blob` 保存：

- 内部 Blob ID和唯一 SHA-256 内容哈希。
- 随机 Object Key、实际大小和真实媒体类型。
- 引用计数。
- 状态 `STAGING`、`READY`、`PENDING_DELETE`、`DELETING`、`DELETED`。
- staging owner token、cleanup token、租约和时间戳。

内容哈希与 Object Key 分离。Object Key 不使用哈希、原始文件名、用户 ID 或逻辑文件 ID。SHA-256 唯一约束决定同一内容只有一个活动物理 Blob。

### 6.3 逻辑文件与授权

`stored_file` 保存随机 fileId、ownerId、blobId、安全展示名、状态 `ACTIVE/DELETED` 和时间戳。相同内容的不同上传创建不同逻辑文件，分别拥有所有者和 ACL。

`file_grant` 保存 fileId、被授权用户、授权者和授权时间。逻辑文件删除时，其授权一并失效。

### 6.4 清理与审计

`storage_cleanup_task` 保存目标类型、目标记录、目标 Key、状态、owner、claim token、租约、尝试次数、下次执行时间和有限失败原因。目标类型至少包含 `TEMP_OBJECT` 和 `BLOB_OBJECT`。

`file_audit_event` 是追加记录，保存服务端生成的内部请求关联 ID、actor、动作、逻辑 fileId、目标用户、决策或传输结果、有限失败分类和时间。不得保存 Token、签名 URL、Object Key、内容哈希、文件内容或原始异常堆栈。

内部请求关联 ID 至少包含 128 位随机熵，不编码用户、资源或时间。客户端追踪 ID只能作为独立字段接收，必须限制长度和字符集，不能覆盖内部关联 ID。

## 7. 上传事务与补偿

上传过程不在长数据库事务中读取文件流：

```text
短事务 A：创建 RECEIVING upload_session、随机 tempKey 和 1 小时过期时间
    ↓
事务外：流式写临时对象，同时计算 SHA-256、累计大小并识别真实类型
    ↓
短事务 B：会话进入 VALIDATED，按 SHA-256 锁定或创建 STAGING Blob
    ↓
事务外：把临时对象提交到随机 Blob Key
    ↓
短事务 C：Blob → READY，创建逻辑文件，引用计数 +1，
          会话 → COMPLETED，并持久化上传审计结果
    ↓
事务后：删除临时对象；失败则创建或保留幂等 TEMP_OBJECT 清理任务
```

具体规则：

1. 数据库事务期间不执行 MinIO 或本地文件 IO，避免持锁等待外部系统。
2. 流写入、大小统计、哈希计算和类型检测在同一数据通路完成，不重复把文件载入内存。
3. 并发上传相同内容时，只有一个会话持有 STAGING Blob 的有效 owner token。其他会话不读取其临时对象，也不访问其上传信息。
4. 遇到其他会话持有的 STAGING Blob 时，使用短间隔、无事务的状态查询进行有界等待；轮询不长期占用连接或行锁。总超时后返回 503，允许客户端重试。
5. 已有 READY Blob 时，新上传在短事务中创建自己的逻辑文件并增加引用，响应行为不显示去重命中；该会话的临时对象进入清理。
6. 物理提交成功但事务 C 失败时，Blob 保持 STAGING。恢复任务依据会话、owner token 和租约完成或回收；STAGING Blob 永不对外提供下载。
7. 逻辑文件创建与引用计数增加在同一事务中，不允许可见文件没有引用或只有引用没有逻辑文件。
8. 事务 B 失败、校验失败、客户端断开或存储写入失败时，会话进入可恢复或终态失败，且不会创建可访问文件或增加 Blob 引用。

状态结果是应用层触发后续动作的统一入口：

```text
BlobReady           → 创建逻辑文件、增加引用、记录上传审计
ReferenceBecameZero → Blob 进入 PENDING_DELETE、创建 Blob 清理任务
AccessGranted       → 写授权审计
AccessRevoked       → 写撤权审计
FileAccessed        → 写授权决策和传输结果审计
```

这些结果在同一数据库事务内转化为持久化状态、任务和审计记录，不引入 MQ，也不依赖事务提交后可能丢失的内存事件。

## 8. 临时对象生命周期

上传会话默认 1 小时过期。应用层以租约批量扫描以下会话：

- `COMPLETED` 或 `FAILED` 且仍有 tempKey。
- `RECEIVING`、`VALIDATED` 或 `FINALIZING`，但会话已过期且租约可接管。
- 已标记 `EXPIRED` 且清理未完成。

临时清理必须同时匹配会话状态、tempKey 和当前 owner/claim token。`RECEIVING` 且租约未过期的临时对象禁止删除。对象不存在视为幂等成功；连接中断、超时和 5xx 进入固定退避；非法 Key、路径越界或状态损坏标记失败并告警。

MinIO 为 `tmp/` 前缀配置 24 小时生命周期规则，作为应用和数据库均不可用时的最终兜底。本地适配器仅扫描配置中明确解析出的临时目录，并使用同样的 24 小时上限。正式 Blob 不使用存储生命周期规则，避免绕过引用和授权模型。

## 9. 删除、引用计数与 Blob 清理

逻辑删除遵循同一短事务：锁定逻辑文件及 Blob，条件标记逻辑文件 `DELETED`，删除有效授权，引用计数减一，记录审计；如果引用归零，同时把 Blob 从 `READY` 改为 `PENDING_DELETE` 并创建唯一清理任务。重复删除不能再次减少引用。

Blob 清理状态为：

```text
READY
  → PENDING_DELETE（引用归零并创建任务）
  → DELETING（清理器取得租约和 cleanup token）
  → DELETED
```

清理器只有在引用仍为 0、状态为 `PENDING_DELETE/DELETING` 且 cleanup token 匹配时才能推进。对象删除在事务外执行；删除成功后以 token 条件标记 `DELETED`。若对象已不存在，则按幂等成功处理。若对象删除成功但数据库提交失败，重试再次观察对象不存在并完成数据库状态。

新上传遇到同一哈希的 `PENDING_DELETE` 或 `DELETING` Blob 时不得直接复活，必须无锁有界等待清理完成。清理完成后，以新 owner token、随机 Object Key 和 `STAGING` 状态条件复用 `DELETED` 元数据行。这样清理器不会删除已经被新上传重新引用的物理对象。

## 10. HTTP API 与下载语义

接口为：

```text
POST   /api/files
GET    /api/files/{fileId}
GET    /api/files/{fileId}/content
POST   /api/files/{fileId}/download-links
PUT    /api/files/{fileId}/grants/{userId}
DELETE /api/files/{fileId}/grants/{userId}
DELETE /api/files/{fileId}
```

上传响应只包含随机逻辑 fileId、安全展示名、识别后的媒体类型、大小和创建时间。不得返回 SHA-256、Blob ID、Object Key、是否去重或其他用户信息。相同内容由不同用户上传时，响应状态与结构一致，但 fileId 不同。

`/content` 在逻辑授权通过并成功持久化授权决策审计后，以流式响应读取本地或 MinIO 对象。对象存储故障不能返回空文件或伪装为 404。传输完成或失败分别追加结果审计。框架必须在提交成功响应前完成授权和首段存储读取；若授权审计写入失败，返回 503 且不开始传输。响应已经提交后发生传输或结果审计失败时无法改写 HTTP 状态，必须终止流、记录结构化错误并增加失败指标，不得记录为成功下载。

`/download-links` 使用相同 ACL：

- 本地适配器生成带 HMAC、逻辑 fileId、签发用户 ID、随机 nonce 和过期时间的链接。兑换时要求同一身份仍已认证，并重新检查文件状态与当前 ACL；撤权或删除立即使链接失效。
- MinIO 适配器生成最长 2 分钟的预签名 GET URL。它是独立 bearer URL，签发后无法重新检查 ACL，撤权后可能在剩余 TTL 内继续访问。
- README 必须明确 MinIO 的残余授权窗口，并建议高风险文件使用 `/content`，而不是预签名 URL。
- 不记录完整签名 URL；审计只记录签发动作、逻辑 fileId 和过期时刻。

## 11. 配置与固定默认值

所有运行参数通过类型安全配置外置，并对范围进行启动期校验。生产默认值固定为：

- 最大文件大小：20 MiB。
- 上传会话有效期：1 小时。
- STAGING Blob 租约：2 分钟。
- 清理批量上限：50。
- 清理租约：30 秒。
- 清理重试间隔：5 秒、30 秒、2 分钟、10 分钟。
- 自动尝试上限：5 次；耗尽后进入 `FAILED` 并保留受控人工重试入口。
- 本地签名链接与 MinIO 预签名 URL：最长 2 分钟。
- 临时对象最终兜底时间：24 小时。

测试配置可以缩短租约、轮询和过期时间，但不能扩大文件上限、允许类型或安全权限。所有租约、领取、重试可用时间和过期判断使用 MySQL 时间；实例时钟只用于非所有权日志时间。

## 12. 错误处理与审计

- 401：缺失或无效身份。
- 404：已认证用户访问不存在、已删除或无权资源。
- 400：非法 Multipart、危险文件名、类型不符、文件超限或无效参数。
- 409：上传会话或 Blob 的不可重试业务状态冲突。
- 503：并发 STAGING 等待超时、数据库不可用、对象存储不可用或安全审计不可用。

API 使用稳定的 UTF-8 JSON 错误结构，不暴露内部路径、Bucket、Object Key、哈希、SQL、堆栈或底层存在性。

上传完成、下载授权、下载链接、授权、撤权和删除属于必须审计的安全敏感操作。授权判断与对应审计写入处于同一短数据库事务；审计写入不可用时失败关闭。拒绝访问也必须写审计；若该审计事务失败，无论目标不存在还是无权访问都统一返回 503，不在响应中暴露目标是否存在。

存储超时、连接中断和 5xx 属于可恢复异常。非法 Key、路径越界、状态损坏和配置错误属于不可自动恢复异常。失败原因必须长度受限、分类稳定且不包含秘密。

## 13. 可观测性

Actuator/Micrometer 暴露低基数指标：

- 上传成功、拒绝和失败计数。
- 活跃与过期上传会话数量。
- 各 Blob 状态数量与 STAGING 最老延迟。
- 临时对象和 Blob 清理积压、最老任务延迟及重试计数。
- 下载授权结果、传输结果和对象存储耗时。
- 授权、撤权和删除结果。

指标标签不得包含用户、fileId、哈希、文件名、Object Key、请求关联 ID 或异常文本。结构化日志可以使用内部请求关联 ID串联同一请求，但不记录完整签名 URL、身份凭证或内容数据。

## 14. 测试设计

### 14.1 单元测试

- 原始文件名清理、CR/LF 注入、路径分隔符和 RFC 5987 输出。
- 实际字节上限及 20 MiB 边界。
- JPEG、PNG、WebP、PDF 签名，扩展名与声明类型一致性。
- 上传会话与 Blob 状态机、owner token 和旧执行者 fencing。
- 引用计数、重复删除、PENDING_DELETE 与 DELETING 规则。
- 私有访问、只读授权、撤权、禁止转授权和管理员不绕过。
- 401、统一 404、400、409 和 503 映射。
- 清理异常分类、固定退避和尝试上限。
- 本地 HMAC 的身份绑定、随机 nonce、过期和篡改校验。
- 审计字段过滤及低基数指标标签约束。

### 14.2 MySQL 集成测试

- Flyway 创建表、检查约束、唯一键和领取索引。
- 逻辑文件创建与引用增加同事务提交或回滚。
- 文件删除、授权失效、引用减少和任务创建同事务提交或回滚。
- 重复授权、撤权和删除幂等。
- 多用户并发上传相同内容只有一个 READY Blob，但产生不同 fileId。
- owner token、cleanup token、租约接管和旧执行者迟到结果。
- 新上传与 DELETING Blob 竞争时不会发生误删或错误复活。
- 事务 B/C 注入失败后，状态最终完成或回收且没有孤儿 READY Blob。

### 14.3 存储集成测试

- 本地适配器的临时写入、提交、流式读取、删除和目录越界防护。
- MinIO 的临时写入、提交、流式读取、预签名和删除。
- 通过 Toxiproxy 验证连接中断、超时、恢复和重试。
- 对象提交成功但数据库最终事务失败后的恢复或回收。
- 清理重复执行、对象不存在、删除成功但数据库完成失败。
- 过期会话可清理，活跃 `RECEIVING` 会话的 tempKey 不会被误删。
- 正式 Blob 不受临时对象生命周期规则影响。

### 14.4 真实 HTTP 集成测试

- Header 适配器必须同时满足允许 Profile 与显式开关；非本地 Profile 误开启时启动失败。
- 缺失、重复、空白和非法身份 Header 返回 401。
- JPEG、PNG、WebP、PDF 上传成功；伪造类型、危险文件名和超限流拒绝。
- 相同内容跨用户上传时状态与响应结构一致、fileId 不同且不返回去重信息。
- 所有者、被授权用户和越权用户的元数据、流式下载与链接申请。
- 不存在、已删除和无权资源具有相同状态、错误结构和可观察字段。
- 授权、撤权、重复操作、禁止转授权和管理员不绕过。
- 本地签名链接在撤权或删除后立即失效。
- MinIO 预签名 URL 在 TTL 内可用并在过期后失败；文档明确残余窗口。
- 中文文件名响应与 `application/json; charset=UTF-8`。
- 审计失败时敏感操作失败关闭；下载传输失败不记录为成功。

### 14.5 并发与故障验收

1. 多用户并发上传同内容，只产生一个 READY Blob 和多个隔离逻辑文件。
2. 事务 B 失败只留下可回收会话和临时对象，不产生可访问文件。
3. Blob 提交后事务 C 失败，恢复任务最终完成或安全回收。
4. 存储超时不增加引用计数，重试不创建重复物理对象。
5. 重复删除只减少一次引用，最后引用只创建一个有效清理任务。
6. 清理租约过期可接管，旧 owner 不能覆盖新 owner。
7. 清理与同内容重新上传竞争时不会删除新物理对象。
8. 应用清理和 24 小时兜底均不误删活跃临时对象或正式 Blob。
9. 无权与不存在资源不通过响应泄露差异。
10. 审计、日志和指标不包含禁止字段或高基数秘密标签。
