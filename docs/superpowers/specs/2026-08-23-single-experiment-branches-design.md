# 单实验分支与文档中心设计

## 目标

将仓库从“实验分支逐步继承前序实验”的累积结构，重整为“一个远端分支只包含一个实验”的隔离结构。`main` 作为唯一文档中心，不再保存任何 `labs/` 实验项目；实验代码、测试、Compose 配置、实验 README 和排障记录只存在于对应实验分支。

`AGENTS.md` 仅作为本机协作配置使用，不再由 Git 跟踪。所有活动分支都必须通过根 `.gitignore` 忽略 `/AGENTS.md`，以后不得提交该文件。

## 当前问题

- `learning/redis-cache` 同时包含实验一和实验二。
- `learning/seckill-inventory` 同时包含实验一至实验三。
- `feat/order-mq-reliable-messaging` 同时包含实验一至实验四。
- 各实验分支重复维护根 `README.md`、学习日志、面试题库和参考记录，导致分支职责不清。
- 当前订单 PR #2 以累积式分支为来源，不符合新的单实验分支模型。
- 本地 `main` 已提交 `AGENTS.md`，订单远端分支和 PR #2 也能访问该提交；文件经审计不含敏感信息，但必须从活动分支和后续提交中移除。

## 目标结构

### `main` 文档中心

`main` 只保留以下内容：

- 根 `README.md`：路线总览、实验状态和跨分支入口。
- `docs/`：设计与实施计划。
- `notes/`：学习日志。
- `interview/`：面试题库。
- `references/`：参考记录。
- `compose/README.md`：共享环境说明文档；不保留实验运行文件。
- `.gitignore`：通用忽略规则，并显式忽略 `/AGENTS.md`。

`main` 不保留 `labs/`。根 README 中的实验入口使用指向对应远端分支和实验目录的明确链接，不能继续使用仅在 `main` 上解析的相对路径。

### 单实验分支

| 分支 | 唯一实验目录 |
|---|---|
| `learning/security-rbac` | `labs/01-security-rbac/` |
| `learning/redis-cache` | `labs/02-redis-cache/` |
| `learning/seckill-inventory` | `labs/03-seckill-inventory/` |
| `feat/order-mq-reliable-messaging` | `labs/04-order-mq/` |

每个实验分支的活动树只能包含：

- 根 `.gitignore`；
- 表中对应的一个 `labs/<实验>/` 目录。

实验分支不得包含根 `README.md`、`AGENTS.md`、其他实验目录、`docs/`、`notes/`、`interview/`、`references/` 或根 `compose/`。

## 历史重整策略

采用“按实验路径过滤历史”，而不是把实验压缩成单个快照提交：

1. 从各实验当前已验收来源创建只保留对应 `labs/<实验>/` 路径的重写历史。
2. 删除过滤后不再修改允许路径的空提交。
3. 在过滤后的分支末端加入根 `.gitignore`，确保 `.env`、构建输出和 `/AGENTS.md` 不会被误提交。
4. 使用 `--force-with-lease` 更新三个已有远端实验分支；若远端头部在执行期间发生变化，必须停止，不能覆盖未知提交。
5. 新建并推送 `learning/security-rbac`。

操作前为 `main` 和三个已有实验分支建立仅本地备份引用，记录原始 SHA。备份引用不推送，验证完成前不得删除。

## `main` 迁移

- 保留文档中心内容并删除 Git 对 `labs/` 的跟踪。
- 删除 Git 对 `AGENTS.md` 的跟踪，但保留本机文件。
- 在 `.gitignore` 中加入 `/AGENTS.md`。
- 更新根 README，使四个实验分别链接到其远端实验分支。
- 保留并迁移当前订单实验的设计、实施计划、学习日志、面试题和参考记录到文档中心。
- 当前工作树中 `labs/02-redis-cache/.env.example` 的未提交本地修改属于用户数据；迁移过程必须先备份并在取消 `labs/` 跟踪后恢复为本机文件，不能覆盖或丢失。

本地 `main` 上引入 `AGENTS.md` 的未推送提交不能直接推送。实施时应重写本地未推送提交，使远端 `main` 的新增历史从未包含 `AGENTS.md`，再提交文档中心迁移。

## PR 与远端处理

- 关闭当前订单 PR #2，因为实验分支不再作为合并到 `main` 的来源。
- 重写后的订单分支继续作为实验四的独立展示与测试分支。
- Redis、秒杀和订单分支使用 `--force-with-lease` 更新；不使用无租约保护的 `--force`。
- 实验分支以后不向 `main` 发起包含实验代码的合并请求。实验验收完成后，只在 `main` 单独提交文档状态和跨分支链接更新。

GitHub 已创建的 PR 记录不能通过普通 Git 分支操作删除。关闭 PR #2 并重写活动分支后，活动分支不再包含 `AGENTS.md`，但旧 PR 页面或 GitHub 内部保留引用仍可能让历史提交可访问。审计已确认该文件没有敏感信息，因此不执行仓库级历史清除或删除仓库等高破坏性操作。

## 后续实验流程

1. 从独立空历史或经过路径过滤的模板创建新实验分支，不能从 `main`、其他实验分支或累积实验树直接派生。
2. 分支只加入根 `.gitignore` 和本实验目录。
3. `AGENTS.md` 可存在于本机工作树，但始终被忽略。
4. 在实验分支运行并记录 Maven/Testcontainers 验收，不修改根 README 或中心文档。
5. 验收通过后，切换到 `main`，仅更新路线、日志、面试题、参考记录和跨分支链接。
6. 禁止把整个实验分支合并回 `main`。

## 验证与回滚

每个重写分支必须执行：

- 枚举完整活动树，确认只存在 `.gitignore` 和一个允许的实验目录；
- 确认不存在根 `README.md` 与 `AGENTS.md`；
- 确认 `.env`、密钥文件、构建输出和 `/AGENTS.md` 均被正确忽略；
- 扫描完整重写历史中的密码、Token、私钥、认证 URL 和个人信息特征；
- 在对应实验目录执行其 Maven 验收命令；
- 比较重写前后实验目录的文件清单和内容哈希，确保没有丢失项目文件。

`main` 必须执行文档链接检查、允许文件清单检查、`git diff --check` 和敏感信息扫描。远端更新后再次读取四个分支与 PR 状态，确认远端头部与本地预期一致。

若任一内容比较、测试、租约检查或远端验证失败，立即停止后续推送。使用本地备份引用恢复对应分支；未经定位原因，不继续重写其他分支。
