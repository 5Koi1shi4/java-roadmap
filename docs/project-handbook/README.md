# Java Backend Roadmap 项目手册

这是一个可复现的学习项目，不是生产部署方案。`main` 分支只维护稳定的文档导航；各实验实现和可复跑验证命令保留在各自独立分支中。

## 项目定位与使用边界

本仓库面向 Java 后端项目化学习：以可验证的实验串联认证、数据一致性、可靠消息、搜索、文件安全、交易平台、服务拆分和 AI 客服。实验的实现不会合并到 `main`；应通过根目录的分支入口进入对应实验，并以其 README 和验收记录为准。真实支付、物流、CAS 与真实模型 API 均不属于当前已验收能力，后续若开展只能作为未来工作并遵循相应合规与服务端配置要求。

## 九个实验的递进路线

1. JWT/RBAC 权限服务建立认证、授权与可撤销 Token 基础。
2. Redis 缓存与一致性处理 Cache Aside、失效和热点重建。
3. 秒杀、库存与接口幂等验证条件扣减、一人一单和幂等边界。
4. 订单状态机与 RabbitMQ 可靠消息通过 Outbox、确认、重试和消费幂等保证可恢复协作。
5. Elasticsearch 商品搜索将 MySQL 事实数据构建为可重建搜索读模型。
6. 安全文件存储以 MinIO 和逻辑授权保护私有文件与证据。
7. 校园交易与服务平台组合交易、库存、支付模拟、售后、消息、搜索和私有媒体。
8. Spring Cloud 渐进拆分把身份与商品读能力提取为独立服务，同时保留交易事实所有权边界。
9. 全栈 AI 校园客服旅程在只读 `ai-support-service` 与 React 客服站点中编排最小状态，并继续由交易服务执行对象级授权。

## 总体能力地图

九个实验沿着“身份与权限 → 数据与缓存 → 高并发一致性 → 异步可靠性 → 可重建读模型 → 私有数据保护 → 交易闭环 → 服务边界 → 全栈 AI 客服”的路径递进。MySQL 保存需要一致性和审计的事实；Redis、Elasticsearch、消息队列和对象存储分别承担缓存、可重建搜索、异步协作和受授权保护的文件能力。

## 全链路数据流

用户经 JWT 访问网关或服务；服务首先在本地数据库完成受事务约束的事实变更，再通过 Outbox、RabbitMQ 与消费者 Inbox 将可重试事件传播到读侧。Elasticsearch 索引和商品读服务投影可以从事实源及事件重新构建；私有文件在对象存储中保存，但访问始终先经过逻辑授权。AI 客服仅编排经过授权的最小状态，模型不接触 Token、原始私人问题、完整交易对象或交易写工具。

## 安全、可靠性与数据所有权原则

- JWT/RBAC 与对象级授权决定访问范围；无权资源和不存在资源保持同构 404。
- MySQL 是交易与关键业务事实源；Redis 缓存、Elasticsearch 索引和商品读投影都不是交易决策来源。
- RabbitMQ 通过 Outbox/Inbox、publisher confirm、租约与 fencing 支持至少一次投递下的恢复与幂等处理。
- MinIO 中的私有媒体和证据受逻辑授权与 ACL 保护；前端 Token 仅存内存。
- AI 客服不能自动退款或裁决；真实模型 API 仅可在明确授权并提供服务端环境变量后作为未来工作启用。
